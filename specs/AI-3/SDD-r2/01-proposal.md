# 01 Proposal

## 结论

批准一个小而完整、完全离线、默认只请求麦克风权限的中文听记 MVP。录音是不可被 ASR 成败连带破坏的主资产，SQLite 是会议元数据与逐字稿真相源，音频是受其引用的本地文件资产。

## 用户价值与可观察结果

- `P-01` 用户一次明确授权麦克风后可开始/停止录音，并始终看见准备、录音、停止、失败状态。
- `P-02` 录音中滚动显示可修正的 partial 与不可原位修改的 finalized 中文字幕。
- `P-03` 停止后，即使模型缺失或失败，已捕获音频仍能保存并播放；finalized 逐字稿按已成功产出的部分保存。
- `P-04` 应用重启后可重开记录；点击 finalized 字幕从其音频时间点回听。
- `P-05` 核心闭环无网络请求、无上传、无账户依赖；用户可删除某次记录及其音频和逐字稿。

## 范围

原生 SwiftUI UI；AVFoundation 单麦克风采集与本地播放；本地 ASR adapter；滚动字幕；SQLite 元数据/事件/逐字稿；本地音频文件；麦克风权限；关键失败恢复和隐私安全日志。

## 非目标

ScreenCaptureKit、Screen Recording、系统音频、双路或来源选择、说话人识别、AI/LLM 摘要、行动项、完整会议记录生成、Markdown/复杂导出、日历、账户、云同步、聊天、付费、移动端、协作、App Store/外部发布均不在范围。不得为“以后可能需要”预埋网络或云接口。

## 隐私目标

- 默认且唯一的 TCC 请求为 Microphone，并由用户操作触发；拒绝后仅解释与提供系统设置入口，不循环弹窗。
- 音频、数据库、模型仅在本机应用容器；日志不得含音频、逐字稿正文、文件绝对路径、用户名或密钥。
- 运行时禁止上传；模型分发只允许显式用户动作下载并校验，下载阶段不接触录音。
- 删除按 `D-12` 执行；崩溃遗留按 `D-11` 恢复。系统备份排除策略须在实现前由 Board 确认，不能宣称安全擦除。

## 成功/退出标准

以 `M-01…M-08` 的证据全部通过作为 MVP 验收。以下是首版 Demo 的暂定成功门槛，不是测量结果：

- 固定语料：公开、允许再分发的普通话语料中 30 分钟 clean read speech 与 30 分钟 office-noise speech（SNR 10–20 dB），各至少 10 名说话人、男女均有；语料清单和 hash 固定。clean CER ≤ 15%，noise CER ≤ 25%；另由 3 名中文母语评审对 20 条盲测句评分，至少 90% 句子获 2/3 评审判定“无需回听即可理解主要语义”。
- 同一固定 60 秒流式夹具，p95 partial 首现延迟 ≤ 1.5 秒，p95 finalized 延迟（语音结束至 finalized）≤ 3.0 秒，端到端 RTF ≤ 0.8。
- ASR 活跃期间进程峰值 resident memory ≤ 3.5 GB；激活模型下载压缩包 ≤ 2.0 GB、落盘模型工件 ≤ 4.0 GB。应用本体另计并单列。
- 连续录音 60 分钟无崩溃、writer frame-duration 对账丢失 ≤ 20 ms，停止后 10 秒内音频进入 committed/recoveryRequired 的确定状态；ASR 失败不得阻止音频保存。
- finalized 字幕点击回听：固定声学标记在开头/中间/结尾各 10 次，目标与实际播放位置绝对误差 p95 ≤ 250 ms，max ≤ 500 ms。

上述指标只在 README 固定基准环境分别报告，重复 3 轮并保留逐轮结果，不同设备不得混合宣称通过。`T-01` 可基于证据建议更换 adapter 或调整门槛，但任何门槛调整都必须经 Board 批准并形成新规格修订。任何范围、隐私、外部服务、持续成本、目录或质量门变化都需升级 Board 并重批完整规格。
