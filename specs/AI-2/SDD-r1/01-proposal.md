# Proposal

## 目标与用户价值

目标是在受控 macOS 环境中证明：用户理解并明确授予麦克风与 Screen Recording 权限后，应用能同时采集麦克风与系统音频，持续显示可信录音状态，停止后生成可定位、可播放、仅存本机的音频文件，并对关键失败给出可恢复说明。

用户价值是降低“会议录到了吗”的不确定性：开始前知道权限和输入是否就绪，录制时知道双路都在工作，停止后能立即播放核验，同时录音默认不离开设备。

## 范围

- 权限用途说明；仅由用户触发请求麦克风与 Screen Recording 权限。
- 同时采集麦克风和系统音频；两路均为必需输入。
- 状态：`idle`、`requestingPermission`、`recording`、`stopping`、`succeeded`、`failed`。
- 用户停止后完成两份本地分轨文件，展示位置、时长、大小并逐一播放。
- 覆盖权限拒绝、单路输入不可用、开始失败、停止失败、写入失败、播放失败。
- 记录非敏感诊断事件；提供构建、测试、异常证据与从零复现步骤的质量门定义。

## 非目标

不包括转写、AI 摘要、行动项、完整会议记录模型、Markdown 导出、云账户、同步、协作、付费、移动端、App Store/外部发布、远端遥测、实时混音、编辑、降噪、回声消除或生产级长时录音保证。未来转写仅定义输入契约，不调用、不实现。

## 假设与约束

- 目标平台最低版本暂定 macOS 13.0，因为采用 ScreenCaptureKit 音频能力；最终部署目标若改变须更新 ADR 并重新审批。
- 用户拥有可用麦克风，系统存在可捕获音频内容，且能手动授权权限。
- 尖刺使用非敏感、人工生成或公开许可测试声音；禁止真实用户录音。
- 产品工件唯一写入目录为 `/Users/shawnx/work/paperclip_project/projects/ai-listener`。

## 风险与缓解

| 风险 | 影响 | 缓解 / 升级条件 |
|---|---|---|
| 两路时钟与格式不同 | 漂移、未来无法对齐 | 分轨保存；记录首帧主机时间、格式和帧数；不在本阶段宣称同步混音 |
| Screen Recording 权限变化需重启应用 | 用户误以为已授权 | 权限检查后给出系统设置路径和“重新检查”；不循环弹窗 |
| 系统无可捕获音频或麦克风被占用 | 无法满足双路 | 原子化启动；任一路失败则停止已启动资源并进入 `failed` |
| 磁盘不足/路径不可写 | 文件损坏或遗留 | 启动前预检；临时扩展名写入；关闭成功后原子改名；失败保留诊断、不宣称成功 |
| 敏感音频或路径进入日志 | 隐私泄漏 | 不记录音频、设备名称、窗口标题或完整文件路径；仅会话 ID、错误码和计数 |
| API/OS 行为差异 | 结果不可复现 | 固定环境记录；真实设备/权限场景必须人工验证；两次同类阻断即升级 |

## 可观察验收结果

| ID | 结果 |
|---|---|
| P-01 | 首次启动不自动触发权限；用户点击开始后看到用途说明并可继续或取消。 |
| P-02 | 两项权限均允许且两路可用时，状态依次可观察为 `idle → requestingPermission → recording`。 |
| P-03 | `recording` 期间 UI 同时显示 microphone 与 system 两路活跃指示和已录时长。 |
| P-04 | 用户停止后状态为 `stopping`；两份文件完成后进入 `succeeded`，两份均可播放。 |
| P-05 | 任一权限拒绝、任一路不可用或开始失败时不进入 `recording`，无被误报为成功的文件。 |
| P-06 | 停止、写入或播放失败进入规定失败呈现，包含可操作恢复建议和稳定错误码。 |
| P-07 | 文件仅位于应用本地容器，未发生网络上传；日志不含音频内容和敏感元数据。 |
| P-08 | 有可审计的构建、单元测试、关键异常、环境与复现证据；“已实现”和“已验证”分列。 |

## 提案停止条件

发生范围/隐私/外部服务/成本/目录/质量门变化，或连续两次同类权限或采集阻断时，停止推进并升级 CEO/Board。Board 未批准 SDD-r1 时，实现保持未开始。
